# equivault-mcp v1.0.1 — Platform Compat Infrastructure

**Shipped:** 2026-04-18
**Platform tracked:** v1.3.x–v1.5.x (unchanged from v1.0.0 — infra release only)
**Tag:** https://github.com/equivault/equivault-mcp/releases/tag/v1.0.1

## Scope

Replace the doc-only platform-version alignment with machine-readable metadata + a runtime check. Surface drift to users before it causes silent failures.

## What shipped

### `equivault` block in `package.json`

```json
"equivault": {
  "platformCompatRange": ">=1.3.0 <1.6.0",
  "platformSurfaceVersion": "1.5.x"
}
```

Declares which platform API versions this MCP release was built for. Machine-readable; consumed by the runtime checker.

### `src/compat.ts` (new)

Dependency-free semver parser + npm-style range matcher + runtime checker.

- `parseSemver("1.6.0")` → `{ major, minor, patch }` or null
- `parseRange(">=1.3.0 <1.6.0")` → `RangeBound[]`
- `satisfiesRange(observed, range)` → boolean
- `evaluateCompat(observed, range)` → `{ status: "ok" | "mismatch" | "unknown" | "invalid-range", ... }`
- `runCompatCheck(observed, range, reporter?)` → `CompatCheckResult` (reporter defaults to `console.error`)

22 unit tests in `tests/compat.test.ts`.

### `EquiVaultClient` integration

- New optional `platformCompatRange` field on `ClientConfig`
- `maybeCheckCompat(response)` reads the `X-EquiVault-Version` response header and runs `runCompatCheck` once per client instance
- Wired into `handleResponse` (get/post/put) AND the DELETE path
- Check runs on success AND error responses (drift is visible even when tools fail)
- Pass `platformCompatRange: null` to disable

6 integration tests covering: warn-once, silent-in-range, silent-missing-header, silent-when-disabled, DELETE-path, error-response.

### `src/index.ts` changes

Now reads its own `package.json` at startup, derives the MCP version from `pkg.version`, and passes `pkg.equivault.platformCompatRange` to the client. Single source of truth — no more duplicate version strings in `src/index.ts`.

## Platform-side coordination

This release **depends** on the platform setting an `X-EquiVault-Version` response header on all `/api/v1/*` responses. The platform does not do this today (v1.5.x). Until it does:

- Observed header is null on every response
- `evaluateCompat` returns `status: "unknown"`
- `runCompatCheck` stays silent (no false positives)
- MCP works exactly as before

The alignment becomes active the moment the platform ships the header. No MCP changes needed at that point.

**Platform-side task** (track in a v1.6.x phase): add `X-EquiVault-Version: {app.version}` to the FastAPI response-middleware stack. ~5 lines of code in `equivault-api/src/main.py` plus a test.

## Release cadence commitment (durable)

The MCP commits to an alignment release within **7 calendar days** of each platform minor ship. See `docs/ALIGNMENT.md` for full policy.
