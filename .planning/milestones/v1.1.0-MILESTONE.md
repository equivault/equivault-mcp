# equivault-mcp v1.1.0 — Platform v1.6.x Alignment

**Status:** Planning (scope freezes when platform v1.6.0 ships)
**Platform tracked:** v1.6.x (Stabilization & Platform Completeness)
**Target ship:** Within one week of platform v1.6.0 ship

## Why this milestone exists

Platform v1.6.0 introduces new API surface that the MCP should mirror. The MCP currently calls the v1.5.x contract; v1.6.0 adds routes (analyst ratings, entitlements snapshot, health-scores, price-targets already landed in Phase 02's contract refresh) plus the OAuth foundation in Phase 03.1. The MCP needs to catch up.

## Trigger

This milestone **freezes scope** when:

1. Platform v1.6.0 is shipped (all 7 phases complete)
2. `equivault-contracts/openapi/v1.json` has drifted forward (new paths, new fields, new error codes) vs the v1.5.x-era contract the MCP was built against
3. The OAuth Phase 03.1 is fully merged (so the MCP can decide whether to add an optional OAuth mode)

## Candidate scope (refine when scope freezes)

Based on what's already visible in v1.6.0 execution:

### Likely new tools

| Tool | Endpoint | Why |
|---|---|---|
| `get_analyst_consensus` | `GET /companies/{id}/analyst-ratings` (new in v1.6) | Surface analyst targets + consensus recommendation |
| `get_health_score` | `GET /companies/{id}/health-scores` (new in v1.6) | Expose computed health-score to Claude |
| `get_price_targets` | `GET /companies/{id}/price-targets` (new in v1.6) | Explicit price-target tool rather than burying under analyst ratings |
| `get_entitlement_snapshot` | `GET /entitlements` (new in v1.6) | Richer than `get_billing_status` — use for pre-flight gate checks |
| `evaluate_feature_flag` | `GET /flags/evaluate/{key}` | Lets Claude know when a feature is behind a flag |

### Likely new options on existing tools

- `get_stock_quote` — expand to support the full set of endpoints surfaced by `equivault-api/src/api/v1/routes/stocks.py` (historical, splits) once the contract adds them.
- Tier map in `translateError` — refresh if the 6-tier pricing changes.

### Likely non-tool changes

- **Optional OAuth mode** — add a `EQUIVAULT_OAUTH_TOKEN` env var as an alternative to `EQUIVAULT_API_KEY`, gated behind the platform's `consumer_oauth_enabled` flag. Use the platform's OAuth flow to mint short-lived access tokens for the MCP when available. Ship as opt-in; API key stays the default.
- **Contract-drift CI gate in the MCP repo** — add a GitHub Action that diffs `equivault-contracts/openapi/v1.json` against a pinned ref; alerts when platform drifts so the MCP can catch up faster next time.
- **Bump `package.json` peerDep ranges** — `zod` v4 migration if the ecosystem has moved by then; `@modelcontextprotocol/sdk` patch-version tracking.

### Stretch (only if low-cost)

- **`ExpertVagabond/glama.ai` registry** — second MCP registry submission beyond awesome-mcp-servers.
- **`mcp.run` / `@claude/mcp-registry`** — whichever is the canonical one at ship time.

## Out of scope

- **Streaming tools** — deferred until MCP spec / SDK supports streaming tool responses.
- **Write-side portfolio tools** — creating/editing portfolios is out of scope for v1.x; read-only access is sufficient for Claude research workflows.
- **Admin tools** — `/api/v1/admin/*` endpoints are intentionally not MCP-exposed.
- **Batch tools** — single-tool-per-call is the right granularity for Claude; batching is premature optimisation.

## Definition of done

- New tools land with TDD + tests + docs (same rigour as v0.3.0)
- `CHANGELOG.md` under `[Unreleased]` covers every new tool + schema change
- `EXAMPLES.md` adds prompts for each new tool
- `README.md` tools table updated

- MCP repo CI green on Node 18/20/22
- Tag pushed; `Publish to npm` workflow runs (and succeeds once `NPM_TOKEN` is set)
- `.planning/equivault-mcp/STATE.md` updated; this file moves to shipped-milestones section
